TẦNG 1/4 • HÀNH VI

🧬 1. Bản sao (Snapshot) hay Liên kết sống (Live)?

M sủa "playlist riêng, A B còn nguyên" → bú Snapshot: C là playlist thường, copy item của A rồi B vào. Sau đó C sống độc lập.

Live (C tự cập nhật theo A, B) nghe sang nhưng kéo thả Manual trong C thành vô nghĩa + phải thêm bảng mới. Đéo đáng lúc này.

Snapshot ✅Live ❌ (YAGNI)

✅ Snapshot ĐỀ XUẤT

A 🌙+B ⚡→ copy →C 🔀
  • 0 bảng mới: C là playlist bình thường
  • Sửa / xóa A → C không đổi
  • Kéo thả, xóa bài, đổi cover trong C: y như playlist khác
  • 4 kiểu sort dùng lại code có sẵn

TẦNG 2/4 • SORT

📅 2. 4 kiểu sort chạy trên C thế nào

Thủ công = đúng thứ tự nối: hết A (theo thứ tự Thủ công của A) rồi tới B. C bật sẵn is_custom_ordered.

Mới / Cũ nhất xếp theo added_at. Mấu chốt: copy luôn ngày thêm gốc, không reset về lúc gộp. Bấm toggle bên phải để thấy khác biệt.

Ngẫu nhiên: như cũ, bấm lại để xáo lại.

added_at gốc0 code sort mới
SortThứ tự trong C (🟧 = từ A, 🟦 = từ B)

TẦNG 3/4 • EDGE CASE

🧨 Mấy ca dễ toang

Toàn là quyết định UX, chốt trước cho khỏi cãi lúc code.

🔁 Bài trùng (A và B cùng có)Giữ 1 bản, ở vị trí xuất hiện đầu tiên (trong A). Preview trong modal báo "bỏ N trùng". DB đã có unique index (playlist, track, segment) lo sẵn.
✂️ Slice vs bài gốcSlice "Điệp khúc" và bài gốc là 2 item khác nhau → giữ cả 2 (đúng luật unique index hiện tại).
1️⃣ Chọn < 2 playlistNút "Tạo" disabled. Playlist rỗng vẫn cho tick nhưng hiện "0 bài".
🏷 TênTự điền "A + B" (≥ 3 cái: "A + B + 1"). Sửa được. Để trống thì bú lại tên tự điền.
🖼 CoverKhông set gì: mosaic 2x2 tự lấy 4 thumbnail đầu như playlist thường.
🧾 Nhớ "gộp từ A, B"?Bỏ (YAGNI). Snapshot rồi, A bị xóa thì dòng này thành rác. Cần thì thêm sau.

LOGIC
mixPlaylists(name, sourceIds)
transaction# lỗi giữa chừng = rollback sạch
c = createPlaylist(name), is_custom_ordered = 1
order = 0
for id in sourceIds# thứ tự tick
for item in getPlaylistItems(id)# = thứ tự Thủ công của nguồn
